request / retry — pick, after, spawn, on

~5% of requests are dropped client-side (drop if rand() < 0.05); the rest are routed by a weighted pick to ok (75%) or fail (25%). On ok the server spawns an ack back to the client; on fail it schedules after 0.6: retry, and on retry re-issues the request. seed makes it reproducible. Counts: document.querySelector('canvas').__flowdot.rt.store.
